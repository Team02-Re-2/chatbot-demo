4. 발견한 점

  1. 팀 모델 v2 단독은 "말로 하는 요구"(책임자·상담원 요구, 신고, 탈퇴, 보상 요구)를 거의 못 잡습니다. 즉시 이관은 1/8입니다. 그래서 챗봇에 규칙 안전장치가 필요합니다. 안전장치를 붙이면 5/8입니다.
  2. 규칙 안전장치도 즉시 이관 3문장을 놓칩니다.
    • "챗봇 말고 상담원이랑 직접 통화하고 싶어요"(#25): "상담원이랑"과 "통화" 사이에 "직접"이 끼어 패턴에 걸리지 않습니다.
    • "반품 기한 지났지만 그냥 전액 환불해 주세요"(#30): 규정 밖 요구인데 "환불"이 문제 제기(1) 패턴에만 걸립니다.
    • "제 체형이면 이 원피스 입었을 때 뚱뚱해 보일까요?"(#31): 예민한 질문을 잡는 패턴이 없습니다.
    • 셋 다 규칙 보완 후보입니다. 이번에는 고치지 않았습니다.
  3. 팀 모델 v2는 불만 뒤에 이어진 차분한 말도 불만으로 봅니다. #39 "아 지금 조회해 보니 오늘 출발했다고 나오네요"와 #40 "네 그럼 내일까지 기다려 볼게요"가 그 예입니다. 그래서 세트 B에서 필요 없는 연결 질문이 나옵니다. 앞 문맥의 불만이 점수에 번지는 것으로 보입니다(추정).
  4. Claude는 네 엔진 중 가장 잘 맞았습니다(38/40). 그러나 같은 문장을 세 번 돌리면 4문장(#14, #16, #32, #38)에서 답이 달랐고, claude.ai 안에서만 돌아갑니다. 공개 배포(GitHub)에서는 규칙 모드만 작동합니다.

5. 한계

  • 40문장은 팀이 지어낸 문장이고 기대 라벨도 팀 제안값입니다. 성능을 일반화할 수 없습니다.
  • 팀 모델 v2 문맥에는 챗봇의 중간 답변을 넣지 않았습니다. 엔진마다 답변이 달라 공정성을 위해 뺐습니다. 실제 챗봇 점수와 조금 다를 수 있습니다. 문맥에 첫 인사말을 넣었을 때 #13 불만 점수는 0.2014였습니다. 챗봇에서 관측된 0.20과 맞았습니다.
  • Claude는 claude.ai 아티팩트가 아니라 Claude Code CLI(claude -p --model sonnet)로 같은 프롬프트를 보냈습니다. 판정만 받도록 도구는 끄고 한 번에 한 문장씩 보냈습니다.
  • 이전 결과표의 "규칙 즉시 이관 7/8"은 고객용 챗봇의 규칙(codebook_rules.js)으로 잰 값입니다. 이번 "규칙"은 주연님 챗봇의 규칙이라 서로 다릅니다. 시험지 파일 안의 "규칙 판정" 열도 고객용 챗봇 규칙 값이므로 이 표의 규칙 결과와 다릅니다.
