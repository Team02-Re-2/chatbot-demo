1. 한눈에 보기

11월 24일 새벽부터 오전까지 챗봇 두 개와 실험 화면 하나를 실제로 열어 대화해 보고, 고칠 것은 고치고, 합치는 방법을 정리했습니다.

한 일결과상태
고객용 챗봇을 브라우저에서 대화 검증이관 기준은 지킴. 잘못된 답 2건을 찾아 고침반영 완료
팀 모델 v2 챗봇 확인모델이 화면에서 실제로 판정함. 약한 불만 문장은 놓침제안 전달
단계 인지형 추천 시연판결함 4건을 고치고 시연 순서를 적음시연 가능
두 챗봇을 합치는 설계안판정은 팀 모델 v2, 답변과 접수는 고객용 챗봇수요일 결정
배포 가능성 확인공개 저장소를 따로 두면 링크 하나로 열림이 페이지가 그 방식

2. 고객용 챗봇 (검증하고 고친 것)

고객이 주문을 고르고, 교환·반품을 접수하고, 필요하면 상담사에게 넘어가는 챗봇입니다. 파일 하나(0.6MB)로 되어 있습니다.

확인한 것

  • 대화 6가지를 규칙 모드와 Claude 연결 모드에서 각각 해 봤습니다.
  • "책임자 바꿔 주세요"는 바로 상담사에게 넘어가고 인계 카드가 나옵니다.
  • 불만이 두 번 쌓이면 넘어갑니다. 교환 접수는 접수번호 발급과 진행 조회까지 됩니다.
  • 지어낸 숫자는 없었습니다.

찾아서 고친 것

문제고친 뒤
"환불은 며칠 걸려요?"에 배송 기간(3~5일)을 답함결제수단을 알면 그에 맞는 안내, 모르면 숫자 없이 결제수단을 되물음
이미 배송완료인 주문을 고르면 접수 카드로 넘어감"이미 배송완료" 안내가 나옴

자동 평가 4종을 다시 돌려 통과를 확인하고 저장소에 합쳤습니다. 아직 못 본 것: Gemini 연결 모드, 낮은 중요도 문제 6건.

3. 팀 모델 v2 챗봇 (팀원 제작, 확인만 함)

우리가 만든 팀 모델 v2(RoBERTa)가 페이지 안에서 직접 돌아가며 고객 말마다 불만 점수와 즉시 이관 점수를 냅니다. 기준선은 0.7입니다. 이 챗봇은 고치지 않았고, 본 것을 제안으로 정리했습니다.

시험결과판단
모델 로딩성공. 약 5분 걸림(안내는 1~3분)미리 열어 두기
"책임자 바꿔 주세요", "상담원 연결해 주세요"바로 연결되고 인계 카드가 나옴정상
"배송이 너무 늦어서 답답하네요"불만 점수 0.20. 기준선 0.7에 못 미침놓침
"그래도 짜증나요 계속 늦어요"불만 점수 0.65. 연결 질문이 뜨지 않음놓침
강한 불만 두 번 → "아니요" → 다시 불만먼저 묻고, 사양한 뒤 다시 불만이 나오면 바로 연결정상
중간 세기 불만즉시 이관 점수 0.74~0.83으로 묻지 않고 연결되는 경우가 있음기준 논의

한 PC에서 한 번 확인한 결과입니다. Claude 판정·답변과 접수 흐름은 보지 못했습니다.

4. 단계 인지형 답변 추천 (시연판)

상담사가 고객에게 보낼 답변을 상담 단계에 맞춰 추천하는 화면입니다. 본인확인 전에는 주문 정보를 말하지 않고, 조회한 정보와 어긋나는 문장은 보내기 전에 막습니다. 고객용 챗봇과는 별개의 실험물이고, 팀 공용 기능으로 정해진 것은 아닙니다.

시연판 열기

3분 시연 순서

  1. 위쪽 가상 상담 버튼에서 “배송 지연”을 누릅니다.
  2. 본인확인 전에는 “먼저 성함과 전화번호 뒷자리를 말씀해 주시겠습니까?” 한 줄만 추천됩니다. 주문 정보 문장은 나오지 않습니다.
  3. “본인확인 완료”를 누르면 “추천 없음 / 조회 정보를 확인해 주세요.”가 나옵니다.
  4. “조회 정보 확인”을 누르면 배송 예정일이 지난 것이 보이고, 배송 기간 안내는 추천되지 않습니다.
  5. “회신 시점” 칸에 “오늘 오후 5시”를 쓰면 사과와 회신 약속 문장이 1순위로 뜹니다. “이 답변 보내기”를 누릅니다.
  6. 상담사 답변 칸에 “내일 도착합니다.”를 직접 써서 보내면 “보내기 차단”이 나옵니다.

이번에 고친 것

문제고친 뒤
배송 예정일이 지났는데 “내일 도착합니다” 같은 약속 문장이 보내짐도착을 약속하는 문장은 보내기 전에 막음
입금 전 주문에 “3~5일 이내 배송” 문장을 추천입금 기한을 입력한 뒤 입금 안내 문장만 추천
끝인사 문장이 매번 다시 1순위로 뜸한 번 보낸 뒤에는 다시 추천하지 않음
본인확인 전에 고객이 취소를 말하면 주문 상태 문장이 바로 추천됨본인확인 질문만 추천

자동 테스트 5종(단언 39개와 화면 점검 2종)을 통과했습니다. 실제 브라우저에서 눈으로 본 것은 고치기 전 판이고, 고친 판은 자동 테스트로만 확인했습니다. 배송 문의 외 유형의 검사와 Claude 연결 경로는 아직 손대지 않았습니다. 시연판 문장은 팀이 쓴 매뉴얼 문장과 지어낸 상담이며, 상담 원문과 문장 단위로 겹치는 것이 없음을 확인했습니다.

5. 두 챗봇을 합치는 방법 (제안)

판정은 팀 모델 v2, 답변·주문 조회·접수·평가는 고객용 챗봇을 쓰는 방식을 권합니다. 고객용 챗봇에는 바깥에서 만든 판정을 받아 넣는 자리가 이미 있습니다.

순서할 일끝났는지 보는 법
0팀 모델 v2 챗봇 소스를 저장소에 올림(시점은 만든 팀원이 정함)저장소에서 파일이 보임
1공통 시험 문장 30~40개와 기대 라벨을 정함표 하나로 합의
2같은 문장으로 세 판정(팀 모델 v2, Claude, 규칙)을 비교문장별 결과표
3고객용 챗봇에 팀 모델 v2 판정을 넣음화면에 점수 표시, 기존 평가 4종 통과
4"연결해 드릴까요?" 먼저 묻기 흐름을 옮김묻기 → 아니요 → 재불만 → 연결 시험 통과
5모델을 못 받을 때 규칙으로 내려가는지 확인인터넷 없이 끝까지 대화

합치기 전에 정할 것

  • 약한 불만 문장(점수 0.20, 0.65)을 어떻게 잡을지. 그대로 둘지, 규칙과 함께 볼지, 기준선을 낮출지.
  • 중간 세기 불만이 묻지 않고 바로 연결되는 것을 그대로 둘지.
  • 기준선 0.7은 팀 결정이라, 바꾸려면 팀 합의가 필요합니다.

시간이 모자라면 발표에서는 두 링크를 나란히 보여 주고 합치는 일은 뒤로 미룰 수 있습니다.

6. 배포

방법되는 것안 되는 것
claude.ai 아티팩트 링크팀 모델 v2와 Claude 답변 전부보는 사람이 claude.ai에 로그인해야 함
GitHub Pages(공개 저장소)규칙 판정과 답변. 누구나 링크로 열림Claude 답변(아티팩트 안에서만 동작)
  • 팀 저장소는 비공개이고 무료 요금제라 그 안에서는 Pages를 켤 수 없습니다.
  • 그래서 이 페이지처럼 보여 줄 파일만 담은 공개 저장소를 따로 만들었습니다. 원본 데이터와 팀 문서는 들어 있지 않습니다.
  • 고객용 챗봇을 여기에 올릴지는 수요일에 정합니다. 올리기 전에 근거 카드에 상담 원문이 없는지 다시 확인해야 합니다.

7. 수요일에 팀이 정할 것

  • 두 챗봇을 합칠지, 하나만 고를지. 판정 엔진은 무엇으로 할지.
  • 고객용 챗봇도 공개 링크로 올릴지, 아티팩트 링크만 쓸지.
  • 팀 모델 v2 챗봇 코드를 저장소에 넣을지와 넣을 위치.
  • 누적 이관 때 "먼저 묻기"를 쓸지.
  • 공통 시험 문장 세트를 만들어 판정 방식을 비교할지.
